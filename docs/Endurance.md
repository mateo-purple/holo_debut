# 耐久配信 v0.1 実装対応

実装順は通常ゲームのDomainとテスト、物理／通常盤面のコード、その共通サービスを利用する耐久Domain・Runtimeです。Unityで通常物理の実動作を確認してから耐久を検収してください。ここでUnity実動作を検証済みとはしていません。

| 20–39 | 2 |

`EnduranceRules` は配列を複製し、`EnduranceSession` は開始時の技能・スタミナ・通常位置を保持します。セッション中の育成はループ規模や基本投球数を変えません。2マスは95以上、規模は2～12の検証があります。

1. `AwaitPlan` のときだけ、現在プレイヤーに一致する `ISubgameSession` を開始できます。開始0番で成功とは判定しません。
2. 投球は共有 `DiceRollController` を1個モードで実行します。無効な物理試行は同じRollTicketで再試行し、`TryAcceptResult` へ届きません。したがって回数とアイテム補正を消費しません。
3. アイテム使用時に共有Inventoryから1個消費し、その効果をpendingとして予約し、追加投球を1回加えます。同一投球の2個目は拒否します。基本回数が残っていても使用可能です。
4. 有効な出目でだけ回数を消費します。予約効果は実際の物理出目を受け取って移動を計算し、1回だけ解除します。ロケットニンジンは3→8歩です。将来の効果も `IDiceItemEffect` が処理し、投球追加と本来の効果を切り離しません。
5. 共有 `PawnMovement` で1歩ずつ進み、各歩で `(P+1)%N` を確定します。途中のEXITでは終了せず、移動をすべて完了してから着地を1回だけ解決します。
6. 奇数は技能XP＋5、偶数は資金＋10,000、0は成功報酬です。1・2・3・4・5回目以降の有効投球に対して50,000／35,000／25,000／15,000／10,000人。RewardServiceのイベントIDと状態の両方で重複を拒否します。
7. 回数が残る間は続行できます。使い切ってアイテムがあれば使用か終了を選択し、なければ失敗します。成功したら残数は破棄し即終了します。途中の技能と資金は結果にかかわらず保持します。
8. 専用盤面・専用駒を非表示にし、通常盤面を再表示します。通常位置、曜日、到着順は耐久処理から書き換えません。終了通知を一度だけ受理して通常手番を一度だけ終了します。

`ChallengeId`、`RollTicket`、処理世代、終了状態を照合し、再開始や終了後のCoroutine／物理コールバックを拒否します。強制出目や物理演出の省略は通常投球にありません。

通常配信との選択地点は仮に10・40・70・100番です。技能XPの換算は試作で1 XP＝技能1、上限100です。これらの補完事項はREADMEにも明記しています。
