## Unityでの検収手順

1. READMEの手順でプロジェクトを開き、コンソールにコンパイル／インポートエラーがないことを確認します。
2. 純粋な通常ゲームを先に確認するにはBoard.assetの `enablePlanning` をOFFにします。2人と4人で開始し、平日2個、休日3個、ゴール後3個を確認します。
3. 通常投球で物理停止と面表示を目視し、1歩ずつの移動、ピンゾロで移動前の再投球、アイテム＋5の一度限りの適用を確認します。
4. Test RunnerのEditModeを実行した後、PlayModeを実行します。80投球の4バッチは実際に完了した件数とJSONの無効理由を確認します。少数試験から完全な公平性は主張しません。
5. 場外、台／床への着地、斜め停止、積み重なり、未停止を故意に作り、無効判定と再試行を確認します。場外以外の故障条件の自動セットアップは未実装なので手動確認が必要です。
6. 通常移動中の再開始、投球中のRetryボタンの条件、フォーカス喪失、押下継続で手番移行、連打を確認します。手番・アイテム・移動・報酬が二重にならないことを確認します。
7. 先に到着した人のゴール後投球と最後の到着での即終了、同率首位の共催カード、同キャラクターのカード重複なしを確認します。
8. 通常盤面の検証後に `enablePlanning` をONに戻し、企画マスで通常配信と耐久をそれぞれ選びます。耐久は1個だけ投げ、専用駒だけ移動し、通常盤面の駒位置・曜日・到着順を変えないことを確認します。
9. 耐久でアイテム前／後、基本残数あり／なし、成功／失敗、再試行、連打、倍速を確認します。移動途中の通過報酬はなく、成功報酬へ通常移動報酬が混ざらないことを確認します。
10. Windows Build SupportがあるEditorで `HoloDebut > Build Windows prototype` を実行し、生成物を起動します。
